# Focus: cutting the Claude Code token bill

The source is a broad catalog of ~30 memory/token tools and practices. Do NOT
list them all. Build the entire presentation around a single thesis:

**"You can cut your Claude Code token bill by more than half by attacking the
three biggest, cheapest sources of waste."**

## How to shape the deck

- **Hook** with a concrete, painful example: a developer burning through their
  window mid-task (verbose tool output, an eternal conversation, the wrong
  model), then the stakes (hitting limits, context rot).
- **Pivot** to the one-sentence key idea above.
- **Deep dive** on the highest-leverage moves only — treat these as the "one
  mechanism" and spend most slides here:
  1. Filter tool/terminal output before it reaches context (input side).
  2. Make the model's replies terse (output side).
  3. Read only what's relevant, and compact at phase boundaries.
  Show a concrete before/after (raw command output vs filtered) rather than
  naming every tool.
- **Zoom out** to the payoff: roughly cutting spend to a fraction of prior, and
  a one-line takeaway.

## What to cut

Mention specific tools only as evidence for the thesis, not as a survey. Skip
the exhaustive per-tool catalog, star counts, and install matrices — those
belong in a README, not on a slide. Keep every slide to one atomic idea and
lead with the concrete example before any abstraction.
